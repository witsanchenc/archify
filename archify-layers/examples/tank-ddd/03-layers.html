结论

两个上下文用同一条依赖规则：应用层和基础设施都指向领域层，领域层不指向它们。

  1. 防腐层只出现在成长一侧。
  2. 合同 battle/contract 不是第四层，它是对战给外面的事件。
  3. 这一页不打开聚合里面的坦克和子弹。

适用于分层提交 2ae47a6b

由什么组成？

对战是应用层、领域层、基础设施。成长多一个防腐层。各层里的类仍是黑盒。1

2

各自负责什么？

层做不做
防腐层把 BattleFinished 译成 BattleResult不改奖励公式
应用层编排流程，发布事件不写胜负和奖励规则
领域层规则、聚合、仓储接口不 import JSON，不 import 应用层
基础设施把聚合写成 JSON不决定何时存

领域层只说存和取。JSON 字段表在基础设施。2

运行入口使用 JSON 实现。内存实现在测试里，主循环不创建它。

3

怎样交互？

允许的方向就是上面两张图里的箭头：调用或实现都指向领域层。领域层不回调应用层。

合同文件刻意不 import 对战内部。防腐层是成长里唯一 import battle.contract 的位置。1

4

生命周期

层本身不会被创建或释放。入口创建基础设施对象，把它传进应用服务。应用服务在开局或读档时得到领域对象。

本层不适用一张状态机。原因：状态属于会话和聚合，不属于“层”这个盒子。
