结论

程序内部分成对战和成长。表现层是唯一同时看见两边的地方，负责把它们接上。

  1. 对战不知道成长存在。
  2. 成长只有防腐层可以 import battle.contract。
  3. 传递的数据只有胜负和剩余命数。

适用于上下文层提交 2ae47a6b

1

由什么组成？

四个黑盒：对战、总线、成长、表现层。共享内核不属于这一层，它在横切。1

图的结构
  • 对战 battle
  • 事件总线 bus
  • 成长 growth
  • 表现层 ui
  • ui → bus · 创建
  • battle → bus · 公布
  • bus → growth · 结算
  • ui → battle · 发指令
  • ui → growth · 读档案
2

各自负责什么？

部分做不做
对战地图、坦克、胜负、对外合同不算分，不 import 成长
成长把合同译成自己的结果，再改档案和榜单不 import 对战内部
表现层按键翻译、组装、绘制不写胜负规则
事件总线把事件交给订阅者不认识业务字段

tests/test_architecture.py 禁止对战 import 成长，也禁止成长的领域、应用、基础设施 import 对战。1

3

怎样交互？

一局结束时，会话把内部的 GameEnded 换成 BattleFinished(won, lives_left)，发给总线。防腐层在同一次调用里把它译成 BattleResult，再交给成长。2 3

图的结构
  • 对战会话 session
  • 总线 bus
  • 防腐层 listener
  • 成长 growth
  • session → bus · 结束事件
  • bus → listener · 同步调用
  • listener → growth · 胜负和命数

对战内部事件 EnemyDestroyed 只订给表现层，不进这条过界路径。入口没有订阅 PlayerHit 和 BaseDestroyed。

4

生命周期

表现层在启动时创建总线，再创建成长和对战，并让防腐层订阅 BattleFinished。这三个对象活到进程退出，源码里没有中途拆掉它们的步骤。3

本层不适用对象自己的状态机。原因：画面状态和胜负状态属于下面的类，这一层只回答谁把上下文装起来。
