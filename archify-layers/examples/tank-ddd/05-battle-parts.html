结论

对战上下文里，会话编排流程，Game 执行一局规则，JSON 仓储负责存档。Game 内部仍是黑盒。

  1. 会话不写碰撞。
  2. 敌方 AI 只能走会话已经打开的 move 和 fire。
  3. 结束时才把内部事件换成合同。

适用于对战构件提交 2ae47a6b

1

由什么组成？

会话、敌方 AI、一局游戏、存档接口和它的 JSON 实现。坦克和子弹不在这张图里。1

图的结构
  • SaveRepository saves
  • GameSession session
  • Game game
  • JsonFileSaveRepository json
  • RandomEnemyAI ai
  • session → game · 创建并调用
  • session → ai · 每格调用
  • session → saves · 存取
  • json → saves

会话另外持有两个 EventDispatcher：自己的 events，以及入口注入的总线。分发规则在横切。

2

各自负责什么？

构件做不做
GameSession画面流程、把指令译成 move 或 fire、发布事件不计算碰撞
RandomEnemyAI每格以 0.5 的概率移动，以 0.2 的概率开火不读键盘，不改规则
Game接受移动、开火和 tick不认识 Command
SaveRepository规定存整局、取最近一局不规定 JSON
JsonFileSaveRepository把聚合写成文件，没有文件时返回空不决定何时存

概率用的是默认 random.Random()，主循环没有传入种子。2

3

怎样交互？

进行中的每一格：先让 AI 行动，再 tick，再把聚合拉出的事件交给内部总线。只有 GameEnded 会变成 BattleFinished。1 3

图的结构
  • 会话 session
  • 敌方AI ai
  • Game game
  • 内部总线 events
  • session → ai · act
  • ai → game · move 或 fire
  • session → game · tick
  • game → session · 事件列表
  • session → events · publish

BattleFinished 的字段是 won 和 lives_left。它不携带坦克坐标。3

4

生命周期

入口创建会话并传入仓储和总线。会话在 START 时用 Game.new_level_1() 换上一局，旧对象不再被引用。LOAD 读到存档后改成暂停。进程退出前没有单独的关闭仓储步骤。1

本层不适用 Game 的胜负状态机。原因：那是聚合自己的状态，在类层。这里只写谁持有会话。
