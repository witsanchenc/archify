整体系统

长图

答

结论

玩家按键，程序推进一局，再把画面画到窗口上。分数和存档落在当前目录的 JSON 文件里。

  1. 对战和成长在这一层都是黑盒。
  2. 两边不直接调用，结束事件经过总线。
  3. 窗口和文件不属于领域规则。

适用于第 0 层提交 2ae47a6b

1

由什么组成？

外界是玩家、窗口和三份 JSON 文件。程序里面先只看成入口、对战、成长和总线。1

窗口和三份 JSON 文件在表里，不放进这张图，避免一行排太宽。

图的结构
  • 玩家 player
  • 程序入口 entry
  • 对战 battle
  • 事件总线 bus
  • 成长 growth
  • player → entry · 按键
  • entry → battle · 指令
  • battle → bus · 公布
  • bus → growth · 合同
2

各自负责什么？

部分做不做
玩家按键、关窗口不判定胜负
游戏窗口显示 pygame 画面不保存规则
程序入口组装并循环不写碰撞
对战一局的地图和胜负不计分数
成长档案、解锁、榜单不摆地图
JSON 文件存放字节不解释规则

总线怎样分发，见下钻。这一层只把它当成通道。

3

怎样交互？

一帧里，入口把按键交给对战，到点再推进一格，然后绘制。成长不在每一帧里结算，只在一局结束时收到合同。1

图的结构
  • 玩家 player
  • 入口 entry
  • 对战 battle
  • 窗口 window
  • player → entry · 按键
  • entry → battle · handle
  • entry → battle · update
  • entry → window · draw

handle 和 update 的内部步骤在构件层。这里对战仍是一个盒子。

4

生命周期

main 创建窗口、总线、成长、对战会话和绘制器，并持有到 pygame.quit()。1

三份文件在存档或结算时写入。进程退出后文件还在磁盘上。入口读写当前目录中的 save.json、profile.json、high_scores.json。它不读 presentation/ 里那两份样例。
