结论

成长侧有两个聚合：档案管累计，榜单管单局名次。它们不认识坦克和地图。

  1. 输入只有 BattleResult。
  2. 胜利才加分。每条剩余命加 1000 分。
  3. 榜单最多 5 条，从高到低。

适用于成长类提交 2ae47a6b

1

由什么组成？

BattleResult 是冻结的值。RewardService 读取它，再调用两个聚合。聚合下面没有实体文件夹。1

图的结构
  • RewardService reward
  • BattleResult result
  • PlayerProfile profile
  • HighScoreBoard board
  • reward → result · 读取
  • reward → profile · 加分
  • reward → board · 提交
2

各自负责什么？

对象做不做
BattleResult携带 won 和 lives_left不含地图，不含坐标
PlayerProfile总分只增、解锁关卡号加 1、胜场加 1不排序榜单
HighScoreBoard收下正分，只留最高的 5 条不记累计胜场
RewardService把一次胜利同时写进两个聚合失败时什么都不改

负数传给 add_score 会抛出 ValueError。restore 重建档案时不发事件。2

submit 在新分数高于当前最高分时记下 NewHighScore，0 和负数直接返回。解锁记下 LevelUnlocked。3

3

怎样交互？

胜利时，剩余命数乘 REWARD_PER_LIFE（1000）得到这一局的分。同一分数既 add_score，又 submit。然后解锁下一关并记一次胜利。1 4

两个聚合互不调用。应用服务负责都保存。

关卡这个词在这里只是整数。它不会让 Game.new_level_1 换一张地图。地图仍只有第 1 关那一张。

4

生命周期

新档案从 0 分、解锁到 1、胜场 0 开始。没有文件时 JSON 仓储就返回这样一份。每次结算替换服务里给界面看的那一份。2

本层不适用状态机。原因：档案和榜单没有命名状态，只有数字变化。上面的表就是全部转移。

5

下钻
